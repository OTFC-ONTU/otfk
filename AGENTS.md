# AGENTS.md — working rules for the otfk project

## Reading order for a new task

1. Your own agent instructions: `CLAUDE.md` for Claude, `AGENTS.md` for Codex. The shared part of these files must be identical; before starting, also check the other agent's file.
2. [ARCHITECTURE.md](ARCHITECTURE.md) — the full reference: route map, DB schema, CI/deploy, **Gotchas** and **PoC-only**. Mandatory before changing any route, migration or workflow.
3. Then the code. When docs and code conflict, **the code wins** (and that is a reason to fix the docs).

## Language policy

- **Russian is not used anywhere in the repository**: not in code, comments, docblocks, tests, docs, commit messages, PR titles/descriptions or branch names.
- Allowed languages: **Ukrainian** and **English**.
  - Code comments and docblocks — Ukrainian (existing convention); English is acceptable.
  - Public UI — Ukrainian (`lang/uk`) and English (`lang/en`); admin panel and service e-mails — Ukrainian.
  - Developer/agent docs (`CLAUDE.md`, `AGENTS.md`, `ARCHITECTURE.md`, `DEPLOY.md`, `docs/*` for developers) — English. `README.md` is for people and stays Ukrainian; documents for college staff (`docs/posibnyk-administratora.md`, guides for editors, privacy policy draft) — Ukrainian.
  - Commit messages and PRs — English or Ukrainian (Conventional Commits prefix: `feat(scope): …`).
- Exceptions (do not translate): archived third-party content and quotations (e.g. Russian-language book titles in `database/content/digital-publications/*.html`, old-site fixtures in `tests/fixtures/`), test data that deliberately checks Cyrillic handling.
- Quick check for Russian-only letters: `git grep -nP '[ыэъёЫЭЪЁ]' -- ':!database/content' ':!tests/fixtures' ':!public/fonts' ':!public/js/filament'`.
- Old commits in `master` with Russian messages (2026-10-08) are not rewritten: `master` is production and shared, rewriting history requires a force push. Only rewrite history at the user's explicit request.

Under `/uploads/`, photos and mirrored documents have different destinations; build the map from verified imports and file_mirrors, not a generic wildcard. ## Code conventions (actual, taken from existing code)

- Comments and docblocks — **in Ukrainian** (see "Language policy"); the public UI uses `lang/uk/layout.php`, `lang/en/layout.php` and the `public.php`/`feature.php` dictionaries of both locales. Move new static labels into the dictionaries; for Alpine use `@js`, for dates/numbers — translation parameters. The admin panel and service e-mails stay Ukrainian.
- URL slugs — Ukrainian transliteration: `/novyny`, `/spetsialnosti`, `/rozklad-dzvinkiv`. Name new routes the same way.
- Indentation 4 spaces (2 for YAML), LF — `.editorconfig`. The `laravel/pint` formatter is installed but not run in CI.
- Bilingual site: `SetPublicLocale` globally detects the language by `/en`, the admin panel is `uk`; `App\Support\LocalizedUrl` builds public links with query/fragment (all public templates, forms, search, RSS/ICS). The shell is translated via `lang/`, the menu — `label_en` in Filament → dictionary of standard labels → original; the translation is computed after the shared cache. `/en` is indexed automatically when the translation is complete and not stale (stage 4); Page/News support optional English fields and separate publication, the static public UI is translated; on the just-test.shop test DB all materials were translated and published on 2026-10-05 (machine translation, needs proofreading), new materials without a translation are shown in Ukrainian; the УКР/EN switcher keeps the material, query and fragment. `LocalizedHtml::links()` changes material hrefs only on output, not in the DB; files and external URLs are kept. Details and remaining stages — ARCHITECTURE.md. Use this mechanism for new public links.
- Page/News translations: `HasEnglishTranslation::localized()` is applied only on public output; do not localize the source attributes (Filament/Telegram use the original). `translation_published` requires title_en and body_en when the source body is non-empty; without a complete published translation the material is shown entirely in Ukrainian. The source hash is updated when the full translation changes/publication is enabled, but not when the original or counters change. English HTML in Filament is a Textarea to preserve markup. The field migration does not fill content; search/suggestions on `/en` use `searchPublic()` over published complete title_en/excerpt_en/body_en, otherwise the original title; Ukrainian search stays on title. Drafts/hidden/future materials are excluded; translations of the other entities are described below, editorial acceptance and SEO remain.
- Specialty/Department/Program translations use the shared `HasEnglishTranslation` with per-model field lists; publishing requires translating all filled-in text fields of the original. Specialty also translates short_description/degree/study_form/duration. A newly filled original field without an English counterpart returns a whole Ukrainian fallback, keeping the flag and hash. Forms/quiz must load the fields for the completeness check; `localized()` is applied only publicly, codes/slug/files and source attributes are shared. Specialty search on `/en` uses `searchPublic()`.
- FAQ/Event/NewsCategory translations use the same mechanism: the main FAQ field is question, answer is also required when the original is filled; Event requires title and translations of filled description/location, category — title. Public output and JSON-LD, ICS/Google calendars and existing event suggestions use the published complete translation with a whole fallback. FAQ answers and event descriptions are plain text; FAQ/event JSON-LD escapes tags via JSON_HEX_TAG. Visibility, ID, slug, dates and URLs are shared; FAQ/categories are not added to search, events remain only in suggestions.
- Staff/QuizQuestion/QuizOption translations: main fields full_name/question/label; Staff requires translations of all filled position/academic_degree/bio. Initials and photo alt are localized only publicly; contacts/photos are shared, bio is still not shown in cards. Every quiz question and option has its own publication/hash; `QuizQuestion::publicPayload()` picks English for the whole group only when the question and all options have a complete published translation. The controller eager-loads all option fields, serialization — `@js`, scores and relations are shared. New/incomplete/draft options return the whole group to the Ukrainian original; an option's state is visible in its Filament section, the question column describes only the question.
- DocumentCategory/Document/Video/Gallery/Photo translations: category — title, document/video/album — title/description, photo — caption; each has its own publication and hash. Document files and YouTube are shared; video description is stored but not shown in cards. Document search uses `searchPublic()`. The gallery uses `albumLocalized()`/`publicCaption()` for a single language for the album and all non-empty source captions; empty captions need no translation. The gallery list eager-loads photos; the lightbox serializes URL and caption via `@js`. The «Переклад альбому EN» column describes only the album, photo states are in the Repeater. Images, dates, order, slug and archive style are shared.
- Banner/QuickLink/StatItem translations: banner — title/subtitle/image_alt/link_label (title is optional; all filled labels must be translated and at least one English text is required), tile/partner — title/description, statistics — label; numeric value is shared. Banner alt is localized only publicly. Setting translates value only for brand_short/brand_name/footer_about/site_description/contact_address/work_hours/announcement_text/site_version_label with type text/textarea. `map()`/`get()` keep originals for internal calls, `publicMap()`/`publicGet()` localize after the shared caches `settings.map`/`settings.translations` (600 s); flush both on SQL edits of settings. Phones/e-mail/URLs/colors/files/Telegram are shared. Brand/description without a published translation use the English dictionary; other values — the original. An empty source text hides the announcement/badge and the `footer_about` paragraph in the footer even with a saved translation. The `/kontakty` text comes from the published CMS page with slug `kontakty`, without it — from settings. `documents.title`/`title_en` — TEXT. Public file links in standalone paragraphs/lists and PDF iframes go through `App\Support\FileCards::render()`; the document catalogue and the OPP list on a specialty page use the shared `x-file-card` (`/spetsialnosti` cards have no files, links to OPP anchors via `App\Support\ProgramAnchors`, output only) (output only, the DB is not changed). A public information section with `document_categories.page_id` (a published non-empty page) shows that page's content instead of the document list (`DocumentCategory::sectionPage()`); the page's own URL is a 301 to the section and excluded from the sitemap. `FileCards` keeps the original manual numbering ("1)", "93.") in the card title. The «Циклові комісії» section on `/struktura` shows the intro and files (rating assessment) from the CMS page `ciklovi-komisiyi`. Licensing with the old-import marker restores nested native details via `Page::publicBody()`/`AccreditationContent`; both locales and URLs are kept. The setting hash includes key/type/value, group does not affect it. Organization JSON-LD escapes tags; RSS language matches the locale.
- EnglishTranslation forms validate the required English fields on first publication or on a change of any translation field (including SEO); saving only the original/service fields is allowed with the previous publication/hash, even if a new source field triggers a whole fallback. Get and record are taken in the context of the specific record, including Repeater. Absolute URLs to the root without a slash before query/fragment are localized by the parsed scheme/host/port/base path; external origins and userinfo are not changed. Heritage-frame uses the public date locale and the English brand from publicGet/the dictionary; the Ukrainian caption keeps config(app.name).
- Admin settings are form pages in the «Налаштування» group (`app/Filament/Pages/*Settings.php`, base `App\Filament\Support\SettingsFormPage`: keys with type in `keys()`, English field `<key>_en` for `Setting::TRANSLATABLE_KEYS`, a filled translation is published, a cleared one is unpublished). Add a new user-facing settings key to the appropriate page, not only to «Розширені налаштування» (`SettingResource`). Menu group order is set by `navigationGroups()` in `AdminPanelProvider`; add a new group there too. Holiday themes — `App\Support\HolidayTheme` (+ `holiday_theme_until`, auto-off by Europe/Kyiv), SVG components `x-holiday.*` with inline styles (the admin preview renders them too; badges use the shared `motif`, the greeting — the shared `greeting`, garlands contain themed pendants), particles — lazy chunk `resources/js/holiday.js`; a new theme requires a `layout.holiday.<key>` greeting in both locales (test `HolidayThemeTest`). No emoji in decorations.
- The main HTML text in the admin panel (Page/News body, Specialty/Department description) is `App\Filament\Forms\Components\HtmlRichEditor`, not a bare `RichEditor`: Filament 4 TipTap with a «Візуально / HTML» switch in the field hint. The standard RichEditor 4 converts HTML into a TipTap document on the server already at load time and saves normalized HTML (iframes, class/style, table widths, comments are lost) — therefore `RichEditorStateCast` is replaced by `HtmlStateCast`: the state is an HTML string as in the DB, only a TipTap document (array) from an edit in visual mode is converted to HTML (`documentToHtml()`: `cleanEditorHtml()` removes TipTap service markup — the `detailsContent` wrapper, colgroup/min-width, colspan/rowspan="1", text-align: start; `<!--imported-from:…-->` markers are re-appended from the source record); `saveFileAttachments()` works only for a document. Client (component view): TipTap 3 emits `update` on `setContent` too, so writing the string into state goes through `write()` with `shouldUpdateState = false` on richEditorFormComponent, returning to visual mode — `setContent(..., { emitUpdate: false })`; any difference of the document from the `baseline` snapshot counts as an edit (normalized `getHTML()` right after loading the text into TipTap, without service markup and trailing empty paragraphs) — keyboard, toolbar, drag-and-drop, image resize; a matching document (TipTap normalization) is rolled back to the original string. Find the wrapper and CodeMirror via `$el.closest('.otfk-html-rich-editor')` (`root()`, `code()`), not `$root`/`$refs`: from the switch button in the hint they point at the x-data of the Filament field wrapper (that is how mode sync was lost); `rich()` returns TipTap data only when `getEditor` exists (before x-load `$data` returns the parent's data). Images — `resizableImages()` (width/height + inline px) and the floating `image` toolbar (buttons «Мале/Середнє/Велике/Уся ширина» = ⅓/½/¾ of the 720 px site column, not larger than the file width, or no size; `setImageSize()` in `html-editor.js` updates `<img>` itself because the node with handles does not re-read width/height). The text area in the editor is a centered 45rem column (as on the site), a photo without size is shown compactly (max-height 16rem) with the note «на сайті — на всю ширину»; on the site `.prose-site img[width]` scales down proportionally (`height: auto !important`). The preview of an unsaved form takes the state via `HtmlRichEditor::rawStateWithHtml()` (TipTap document → HTML; otherwise an array reached the preview and "doc" was printed). For markup that TipTap simplifies (`HtmlRichEditor::LOSSY`/`isLossy()`, the pattern is shared by PHP/JS; details, tables and thead, sized images, alignment, iframe are not lossy; `<a name>`, `details open`, srcset/sizes/download/lang/dir are lossy) — a warning and confirmation of the first edit. An image uploaded in visual mode and saved from HTML mode (a string with a temporary-upload `<img data-id>`) is moved to permanent storage in `saveFileAttachments()` without normalizing the rest of the HTML; the `baseline` snapshot waits for TipTap without a limit; Ctrl/Cmd+S first flushes pending CodeMirror input; an external replacement of the CodeMirror document does not enter the undo history. Double quotes `"` inside JS in `x-data` break the attribute — do not use them. HTML mode — CodeMirror 6 (Vite entry `resources/js/admin/html-editor.js` via a panel render hook, lazy chunk; the `.cm-activeLine` background in the `html-editor-codemirror.js` themes is semi-transparent only: the selection layer lies under the text, an opaque background hid the selection in the cursor line) with auto-formatting `resources/js/admin/html-format.js`: line breaks only around block tags, text/inline/pre/comments untouched. Above the code — buttons «+ Розгортний блок» and «Розділи → розгортні блоки» (`resources/js/admin/html-sections.js`, test `tests/Frontend/HtmlSectionsTest.mjs`; nesting — select a heading with blocks and press «+ Розгортний блок»). Visual-mode toolbar: H2–H4, alignment, lists, quote, rule, table, collapsible block, «PDF / відео», attachments (`getDefaultToolbarButtons()`). The visual-mode «Розгортний блок» button is `wrapInDetails()` in `html-editor.js` (like `detailsSnippet()` in HTML mode): the heading at the start of the selection (or the first paragraph when several blocks are selected) becomes the summary, the rest becomes the content; H2–H4 with the cursor in a block summary (the TipTap `detailsSummary` schema is text-only) unfold the block back — `heading()`: summary → heading of that level, content below it. The handlers are replaced in `HtmlRichEditor::getTools()` (without the script — standard Filament commands). The «PDF / відео» button is the plugin `App\Filament\Forms\Components\RichEditor\EmbedPlugin`: a modal (link or PDF upload to `storage/app/public/documents/vbudovani`, title), the address is normalized by `App\Support\EmbedSource` (youtu.be/watch/shorts → `youtube.com/embed/ID?start=`, Drive/Docs → `/preview`, map — embed address only, own site → relative path, the result is checked by `IframeSourceSanitizer::allowed()`), an `<iframe>` is inserted with the import attributes (`class="w-full" style="min-height:24rem;border:0" loading="lazy"`, for video also allow/allowfullscreen/referrerpolicy). The TipTap `embed` node is the pair `EmbedExtension` (PHP) and `public/js/admin/rich-editor-embed.js` (a static ES module, no build; takes TipTap from `window.FilamentRichEditor.tiptap`, shows a card in the editor without loading the iframe) with a shared attribute list; existing iframes open in visual mode losslessly (the `<p>` wrapper around them disappears — FileCards handles both forms). On the site a PDF iframe → file card (FileCards), video — player. Test `EditorEmbedTest`. Research of options — `docs/editor-research.md`. Component styles — inline `@once` in its view. Test `HtmlRichEditorTest`. CMS hub: a short body (≤800 characters) is the intro above the cards via `HubIntro::withoutChildLinks()` (on output only, hides paragraphs/items ≤200 characters that lead to child pages), a long one is the «Про розділ» article below the cards; the hub sidebar has contacts only.
- All native `<details>` inside `.prose-site` are styled as a single accordion (like the restored licensing panels `.content-accordion`); new collapsible content in the CMS is plain `<details><summary>`, without custom classes or inline styles.
- Long-text cards `.prose-site`/`.heritage-frame` are `max-w-none`: they fill the available container or the column next to the table of contents; do not bring back the narrow `65ch` limit (test `HeritageProseTest`).
- Bell schedule: two shifts, shift 1/2; `BellPeriod::active()` sorts by shift/starts/id, the `bell_periods.v3` cache is flushed on saved/deleted. Live highlighting by ID shows all simultaneous periods; breaks are computed within a shift after the maximum end of the previous intervals. The admin page `BellSchedule` edits 4 periods per shift and the flags `bells_second_shift`/`bells_now_chip`; do not return to a single ungrouped list.
- Wrap public HTML tables with `ResponsiveTables::render()` on output, after link localization; do not rewrite the source HTML in the DB. Scrolling is on `.content-table-scroll` with `contain:inline-size`, the table itself is `display:table` and full width; do not bring back `display:block` on the table.
- Public addresses are never lost (test `PublicUrlRedirectsTest`): models Page/News/Specialty/Department/Gallery/Staff use the trait `App\Models\Concerns\KeepsPublicUrls` (`publicRouteName()`, `publicFallbackPath()`, `wasPublic()` based on original values; for News — with the date). Changing the slug of a published material → `App\Support\PublicUrlRedirects::moved()` writes a 301 old→new into `legacy_redirects` for `/…` and `/en/…`, retargets active records pointing at the old address (with #anchor/query), disables a record whose source is the new live address (otherwise a chain); deleting a published material → `removed()` to the section/list (Page — published parent or `/`, News — `/novyny`, Staff — department). Incoming records are found by `target_path_hash` (as the model checks), manual admin records (note not starting with «Автоматично») are not overwritten — a record disabled when an address came back to life is re-enabled with its own target when the material is deleted; a target that itself redirects (a document section page, «Викладачі комісії») is replaced by the final one. Map errors do not break saving (logged). Subpages of a deleted Page move to its parent (`deleting`). In the admin panel deletion is `App\Filament\Support\SafeDeleteAction` (`make()` on Edit pages, `bulk()` in the tables of pages, news, galleries and staff): the modal lists the consequences, button «Зняти з публікації» (with edit permission; warns that the address will return 404 until republished); `bulk(Resource::class)` checks `canDeleteAny`/`canDelete` per record; blocks (also with a server-side `before` check) a Page used in the menu (`menu_items.page_id`), a document section page and `Page::PROTECTED_SLUGS` — addresses the code relies on (abituriyentu, studentu, istoriya, kontakty, zvorotniy-zvyazok, ciklovi-komisiyi, litsenzuvannya-ta-akredytatsiya, osvitno-profesiyni-prohramy, polityka-konfidentsiynosti; their slug field is disabled). Add any new slug hard-coded in code to this list.
- Admin menu — groups by where the material lives on the site (`navigationGroups()` in `AdminPanelProvider`, test `SettingsPagesTest`): «Новини та події» (news, categories, events, galleries, videos), «Головна сторінка» (banners, tiles, «Коледж у цифрах»), «Сторінки та меню» (pages, menu, «Що наповнити», «Биті посилання»), «Вступ і навчання» (specialties, OPP, quiz, FAQ, bell schedule), «Структура та персонал», «Публічна інформація», «SEO», «Налаштування»; order within a group — `navigationSort`. The reorder-mode button is labelled «Змінити порядок»/«Готово» (`reorderRecordsTriggerAction` in `Table::configureUsing`); do not make the mode permanent: row actions are hidden in it and a record is easy to move by accident. Bulk actions (row checkboxes) — only in long lists (news, pages, documents, galleries, events, staff, redirects, 404 log); short ordered reference lists have no `toolbarActions` (test `DragReorderTest`).
- Record order in the admin panel is set only by drag-and-drop (button «Змінити порядок»), forms have no numeric `sort_order` field: 16 resources (banners, videos, galleries, specialties, document categories, documents, departments, tiles, pages, staff, menu, FAQ, statistics, news categories, educational programmes, quiz questions) — `->reorderable('sort_order')`, the number column is hidden by default. The list page uses the trait `App\Filament\Support\ReordersBySwappingPositions`: the shown records swap their numbers (with a search/filter hidden ones do not move), saving goes through the model without `updated_at` (cache flushes fire — standard Filament writes a direct UPDATE and would not flush `menu.navigation`/sitemap). Models — trait `App\Models\Concerns\HasSortOrder` (a new record without `sort_order` → max+1, at the end; for "newest on top" feeds — Gallery/Video/Document/Banner, `sortNewRecordsFirst()` — min-1, first, as previously by date). Duplicate numbers were renumbered once by migration `2026_10_09_120000` in site order (sort_order + tie-breakers from `scopeOrdered`/relations); a new ordered model needs both traits and unique numbers (reorder mode sorts only by sort_order, then id). Test `DragReorderTest`.
- Public controllers are thin; lists go through model scopes (`published`, `ordered`, `active`, `visible`). Auto-slug — in the models' `booted()`/`saving`.
- Admin security (contracts `AdminRolesTest`/`AdminSecurityTest`/`AdminExposureTest`): roles `users.role` = `admin`|`editor` (`User::ROLES`, `isAdmin()`); «Користувачі», «Розширені налаштування», «Меню навігації», the «SEO» group («Редиректи старих адрес», «Журнал 404», settings page `SeoSettings` «Розмітка та аналітика») and all pages inheriting `SettingsFormPage` — `admin` only, via `canAccess()` + policies inheriting `App\Policies\AdminOnlyPolicy` (auto-discovered by model name) + a repeated `abort_unless(static::canAccess(), 403)` in Livewire actions (`save()`, `sendTest()`). For a new resource/page decide the role right away and add a test; content is available to the editor. `User::booted()` forbids deleting yourself/the last `admin`, demoting the last `admin`, an unknown role; bulk deletion of users is disabled. `UserFactory` creates an `admin` by default, `->editor()` — an editor; `DatabaseSeeder` requires `ADMIN_PASSWORD` outside `local`/`testing` and does not overwrite the password (`firstOrCreate`).
- Uploads: `config/livewire.php` sets `extensions:` + `mimetypes:` for all temporary uploads (jpg/png/gif/webp/pdf/doc(x)/xls(x)/ppt(x)/odt/ods/odp; SVG/HTML/PHP are rejected) + `max:20480`; a new `FileUpload` — `acceptedFileTypes` + `maxSize` within this list. `storage/app/public/.htaccess` (in git via `!.htaccess`) forbids script execution and sets CSP `sandbox` on HTML/SVG/JS — do not remove or weaken it. Editor HTML — cast `App\Casts\SafeHtml` (`HtmlSanitizer` on `symfony/html-sanitizer`: a DOM parser with an allow-list, iframes only via `IframeSourceSanitizer` — YouTube/Google Maps/Docs/Drive/own site; `<!--imported-from:…-->` markers are preserved separately; do not bring back the regex variant — `AdminSecurityTest` contains its bypasses) on `body`/`body_en` of Page/News, `description`/`description_en` of Specialty/Department, `bio`/`bio_en` of Staff; a new HTML field — the same cast; the sanitizer normalizes markup on save (`<tbody>`, `<img />`, attribute quotes), so tests compare the saved HTML with a normalized expectation, not with the source string; any `json_encode` inside `<script>` — with `JSON_HEX_TAG`; link fields — the rule `App\Rules\SafeUrl`. `SecurityHeaders` is also in the panel stack (`frame-ancestors 'self'`, `X-Robots-Tag: noindex` for `/admin*`/`/livewire/*`); there is no public link to `/admin`. Password policy — `Password::defaults()` (12+, letters and digits, `uncompromised()` in production). Login log — listener `App\Listeners\LogAuthenticationEvents` (login/failed/logout) and `App\Filament\Auth\Login::getRateLimitedNotification()` (lockout; Filament does not fire the `Lockout` event; the class is outside `Filament/Pages` to stay out of auto-discovery) → channel `security` (`storage/logs/security-*.log`, 90 days) and `users.last_login_at/ip`. `User::$attributes` sets role `editor` by default; deletion in `UserResource` goes through `guardDeletion()` (a notification instead of an exception). In tests `TestCase::setUp()` resets `Paginator::useTailwind()` — `Livewire::test()` of a table with 403 on mount does not restore the static pagination view. `composer audit --locked` in CI is blocking, `composer.json` pins `platform.php = 8.3.0`: update dependencies patch/minor without `Downgrading`, do not disable the audit step. `deploy.yml` runs the tests and audit itself (job `tests`, `needs`) and deploys `${{ github.sha }}` to the server (`git fetch origin <sha>`, also works for a manual run from another branch) — do not bring back `origin/master`. The script ban in `/storage/` is duplicated by `RewriteRule … [F]` in `public/.htaccess`. `style` goes through `StyleAttributeSanitizer` (allow-list of CSS properties), `class` — `ClassAttributeSanitizer` (no fixed/absolute/inset/z/opacity/translate/w-screen utilities etc.; add new public overlay utilities to its block-list). Second factor: `RequireTwoFactor` is in the panel's `authMiddleware` and `persistentMiddleware`, the 2FA pages are `App\Filament\Auth\*` (outside auto-discovery, in `->pages()`, trait `SimpleAuthLayout`); new panel components need to do nothing, but a new component that is "public before the factor" must be added to `RequireTwoFactor::ALLOWED_COMPONENTS`. In tests `actingAs()` gives a fixture factor, `actingAsWithoutTwoFactor()` does not; do not disable enforcement in application code. Reset: «Скинути 2FA» (not for yourself), `otfk:two-factor --reset`, `TWO_FACTOR_ENFORCE=false`.

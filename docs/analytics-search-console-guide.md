# Search Console, Bing і Google Analytics: покрокова інструкція

Для працівника коледжу, який відповідає за сайт (власник облікових записів), і для адміністратора сайту. Мета — зберегти історію пошукової видимості старого сайту, правильно підключити нові інструменти й не загубити доступи, коли новий сайт замінить старий на тій самій адресі `https://otfk.od.ua/` (плановий запуск — жовтень–грудень 2026). Загальний план робіт — [seo-plan.md](seo-plan.md), робота в адмінці — [посібник адміністратора](posibnyk-administratora.md).

> Назви кнопок і меню Google та Microsoft періодично змінюються. Нижче вони наведені за станом на жовтень 2026 року (англійською, як в інтерфейсі за замовчуванням, і українською, якщо інтерфейс перекладено). Якщо пункт не знайшовся — шукайте за змістом або відкрийте посилання на офіційну довідку в кінці кожного розділу.

## 0. Головні правила

- **Усі облікові записи створюються на офіційний Google-акаунт коледжу** (не на особисту пошту працівника чи розробника). Власник — коледж; розробник отримує лише запрошення з обмеженими правами, яке можна відкликати.
- Логін і пароль акаунта коледжу зберігаються у відповідальної особи (і в резервної), з увімкненою двоетапною перевіркою. Паролі й коди не пересилати в месенджерах і не вписувати в документи.
- Ідентифікатори (наприклад, `G-XXXXXXX` для Google Analytics) секретом не є — їх можна записати в цей документ або передати розробнику.
- Інструмент Google **«Зміна адреси» (Change of address) НЕ використовується**: домен лишається тим самим, змінюється лише «начинка» сайту.

## 1. Google Search Console — зараз, до запуску

Search Console показує, за якими запитами сайт знаходять у Google, які сторінки проіндексовано і хто на них посилається. Історія зберігається лише 16 місяців, тому вивантажити її треба **до** заміни сайту.

### 1.1. Перевірити, чи ресурс уже існує

1. Увійдіть в акаунт коледжу і відкрийте https://search.google.com/search-console.
2. Ліворуч угорі — список ресурсів (property). Шукайте один із варіантів:
   - **Ресурс домену** — `otfk.od.ua` (без `https://`). Підтверджується записом DNS TXT у реєстратора/хостингу домену; охоплює всі адреси (http/https, з www і без). Найкращий варіант, бо **не залежить від файлів на сайті** і переживе заміну сайту.
   - **Ресурс з префіксом URL** — `https://otfk.od.ua/`. Може бути підтверджений HTML-файлом, мета-тегом, Google Analytics або Tag Manager. Такі способи **зникнуть разом зі старим сайтом**.
3. Якщо ресурс є — відкрийте **Settings (Налаштування) → Ownership verification (Підтвердження права власності)** і запишіть спосіб підтвердження. Якщо там лише файл чи мета-тег старого сайту — додатково підтвердьте ресурс через DNS (див. 1.2), інакше після запуску доступ може зникнути.
4. **Settings → Users and permissions (Користувачі й дозволи)** — перевірте, хто має доступ. Колишніх працівників і сторонніх осіб видаліть; власником (Owner) має бути акаунт коледжу.
5. Якщо ресурсу немає або ви не знаєте пароля акаунта, з яким його створено, — попросіть доступ у попереднього власника (видно в «Users and permissions», якщо хтось вас уже додавав) або створіть ресурс домену заново за 1.2. Історію даних Google показує будь-якому підтвердженому власнику.

### 1.2. Додати ресурс домену (якщо його немає)

1. Список ресурсів → **Add property (Додати ресурс)** → **Domain (Домен)** → введіть `otfk.od.ua` → Continue.
2. Скопіюйте запропонований TXT-запис `google-site-verification=…`.
3. Передайте його тому, хто керує DNS домену (реєстратор або панель хостингу; уточнити, де обслуговується домен `od.ua`). Запис додається до кореня домену, тип TXT.
4. Через 10 хвилин – кілька годин натисніть **Verify (Підтвердити)**. TXT-запис **не видаляти** ніколи — він тримає підтвердження.

Довідка: [Додавання ресурсу](https://support.google.com/webmasters/answer/34592?hl=uk), [підтвердження права власності](https://support.google.com/webmasters/answer/9008080?hl=uk).

### 1.3. Дати доступ розробнику

**Settings → Users and permissions → Add user (Додати користувача)** → пошта розробника → дозвіл:
- **Full (Повний)** — бачить усі звіти й може надсилати sitemap і запити на індексацію. Рекомендовано на період перенесення.
- **Restricted (Обмежений)** — лише перегляд.

Власником (Owner) розробника не робити. Після завершення робіт права можна зменшити або відкликати.

### 1.4. Що вивантажити зараз

Збережіть файли в спільну папку коледжу (наприклад, Google Диск акаунта коледжу → «Сайт / SEO / до перенесення 2026») і дайте доступ розробнику. Назва файлу — з датою вивантаження.

| Що | Де в Search Console | Як |
|---|---|---|
| Запити (Queries) за 16 місяців | **Performance (Ефективність) → Search results** | Угорі «Date: Last 3 months» → змініть на **Last 16 months**; позначте «Total clicks», «Total impressions», «Average CTR», «Average position»; вкладка **Queries** → **Export (Експорт)** → Google Sheets або CSV. |
| Сторінки (Pages) за 16 місяців | Той самий звіт, вкладка **Pages** | Export. Окремо корисно вивантажити по країнах і пристроях (вкладки Countries, Devices). |
| Стан індексації | **Indexing → Pages (Індексування → Сторінки)** | Export: список проіндексованих сторінок і причини неіндексації. Відкрийте кожну причину з таблиці внизу та вивантажте приклади URL. |
| Зовнішні посилання | **Links (Посилання)** | Блок **Top linked pages (external)** → More → Export; також **Export external links → More sample links / Latest links**. Це адреси, на які посилаються інші сайти, — для них обов'язкові редиректи. |
| Старий sitemap | **Sitemaps (Файли Sitemap)** | Запишіть адреси надісланих sitemap і їх стан; відкрийте кожен у браузері й збережіть файл (Ctrl+S). |

Обмеження: експорт з інтерфейсу дає до 1000 рядків на таблицю. Якщо рядків більше — повідомте розробника: повні дані можна отримати через Looker Studio або Search Console API. Довідка: [звіт «Ефективність»](https://support.google.com/webmasters/answer/7576553?hl=uk), [звіт «Сторінки»](https://support.google.com/webmasters/answer/7440203?hl=uk), [звіт «Посилання»](https://support.google.com/webmasters/answer/9049606?hl=uk).

### 1.5. Після запуску нового сайту

1. **Sitemaps** → у полі «Add a new sitemap» введіть `sitemap.xml` → **Submit (Надіслати)**. Старий sitemap, якщо його адреса інша, видаліть зі списку через кілька тижнів.
2. **URL inspection (Перевірка URL)** — у верхньому рядку пошуку вставте адресу → дочекайтеся результату → **Request indexing (Надіслати запит на індексування)**. Робіть це по черзі для пріоритетних сторінок: головна, сторінка вступу (`/abituriyentu`), каталог спеціальностей (`/spetsialnosti`), ключові спеціальності, контакти (`/kontakty`). Кожну адресу — один раз; повторні запити не прискорюють обхід, а денна квота обмежена.
3. Запишіть у таблицю (розділ 5) дату й перелік надісланих адрес.
4. Перший тиждень — щодня, далі щотижня: Indexing → Pages (нові помилки 404/5xx), Performance (падіння показів), а також журнал 404 в адмінці (група «SEO»).

Довідка: [повторний обхід](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl?hl=uk), [надсилання sitemap](https://support.google.com/webmasters/answer/7451001?hl=uk).

## 2. Bing Webmaster Tools — зараз, після Search Console

Bing (і пошук на його основі) використовує окремий кабінет. Найпростіше — імпортувати сайт з Search Console.

1. Відкрийте https://www.bing.com/webmasters і увійдіть **тим самим Google-акаунтом коледжу** (кнопка Google).
2. Оберіть **Import your sites from GSC (Імпорт із Google Search Console)** → Continue → дозвольте читання даних Search Console → позначте `otfk.od.ua` → **Import**. Разом із сайтом імпортуються sitemap.
3. Якщо імпорт недоступний — **Add your site manually** і підтвердіть через DNS-запис (CNAME) або іншим запропонованим способом, крім файлу/мета-тега на старому сайті.
4. **Settings → Users** — додайте розробника з роллю **Administrator** або **Read/Write** на час перенесення.
5. Після запуску: **Sitemaps** → перевірте/надішліть `https://otfk.od.ua/sitemap.xml`; для окремих сторінок — **URL Inspection** або **URL Submission**.

Довідка: [імпорт з Search Console](https://blogs.bing.com/webmaster/2019/9/Import-sites-from-Search-Console-to-Bing-Webmaster-Tools/), [довідка Bing Webmaster](https://www.bing.com/webmasters/help).

## 3. Google Analytics 4 — безпосередньо перед запуском

GA4 рахує відвідувачів і їхні дії на сайті. На новому сайті аналітика **завантажується тільки після того, як відвідувач натисне «Прийняти»** у банері cookies, лише на основному домені otfk.od.ua і не для працівників, що увійшли в адмінку. Сайт сам надсилає три події: `click_phone` (клік на телефон), `click_email` (клік на e-mail) і `file_download` (клік на файл). Безкоштовної версії GA4 достатньо.

Якщо в коледжу **вже є** ресурс GA4 для otfk.od.ua — не створюйте новий: перевірте, що власник — акаунт коледжу, і пройдіть кроки 3.3–3.8 у ньому (історія збережеться).

### 3.1. Обліковий запис і ресурс

1. Відкрийте https://analytics.google.com під акаунтом коледжу → **Start measuring (Почати вимірювання)** (або **Admin (Адміністратор) → Create → Account**, якщо акаунти вже є).
2. **Account name (Назва облікового запису)**: «ОТФК ОНТУ». Налаштування обміну даними (Data sharing settings) — зніміть позначки з усього, крім технічної підтримки (Technical support), за бажанням.
3. **Property (Ресурс)**: назва «otfk.od.ua»; **Reporting time zone** — Ukraine (GMT+02:00/+03:00, Kyiv); **Currency** — Ukrainian Hryvnia (UAH).
4. Відомості про організацію: галузь — Education (Освіта), розмір — за фактом; мета — «Understand web and/or app traffic» або аналог.
5. Погодьтеся з умовами Google Analytics (Terms of Service) для країни «Ukraine» — це робить відповідальна особа коледжу.

### 3.2. Потік даних і ідентифікатор

1. **Choose a platform → Web (Вебсайт)**.
2. **Website URL**: `https://otfk.od.ua`; **Stream name**: «otfk.od.ua — сайт».
3. Перемикач **Enhanced measurement (Покращене вимірювання)** залиште увімкненим, але натисніть на шестерню біля нього і **вимкніть «File downloads» (Завантаження файлів)** — сайт сам надсилає подію `file_download`, інакше кожен файл рахуватиметься двічі. Решту (Page views, Scrolls, Outbound clicks, Site search, Form interactions, Video engagement) можна лишити.
4. **Create stream** → скопіюйте **Measurement ID** вигляду `G-XXXXXXXXXX` (у правому верхньому куті сторінки потоку). Пізніше його можна знайти: **Admin → Data collection and modification → Data streams → потік**.
5. Сторінку з кодом установлення (Installation instructions / Google tag) **пропустіть** — код уже вбудований у сайт.

### 3.3. Приватність і зберігання

У **Admin (Адміністратор)** → розділ **Data collection and modification (Збирання та змінення даних)**:
- **Data collection (Збирання даних)** → **Google signals data collection** — **вимкнено**. Там же **Granular location and device data collection** — можна вимкнути (менше точних даних про місцеположення).
- **Data collection** → блок про персоналізацію реклами (**Allow ads personalization** / Advanced settings to allow for ads personalization) — **вимкнути для всіх регіонів**.
- **Data retention (Зберігання даних)** → **Event data retention** — **14 months**; **Reset user data on new activity** — вимкнути. Збережіть.
- У розділі **Product links (Зв'язки з продуктами)** нічого не підключайте (Google Ads тощо не використовується).

### 3.4. Внутрішній трафік (необов'язково)

Працівники в адмінці й так не враховуються. Якщо треба також виключити комп'ютери коледжу:
1. **Admin → Data streams → потік → Configure tag settings → Show more → Define internal traffic** → Create: назва «Коледж», `traffic_type` = `internal`, умова «IP address equals» — зовнішня IP-адреса мережі коледжу (дізнатися в ІТ-відповідального).
2. **Admin → Data collection and modification → Data filters** → фільтр «Internal Traffic» спершу у стані **Testing**, через кілька днів перевірки — **Active**.

### 3.5. Ключові події

Події з'являються в GA4 після того, як хтось на сайті їх викличе (першого дня після запуску достатньо самостійно клацнути телефон, e-mail і файл, погодившись на cookies). Далі: **Admin → Data display (Відображення даних) → Events (Події)** → у рядках `click_phone`, `click_email`, `file_download` поставте позначку **Mark as key event (Позначити як ключову подію)**. Якщо подій ще немає — **Key events → New key event** і введіть назву точно, малими літерами.

### 3.6. Доступ розробнику

**Admin → Property access management (Керування доступом до ресурсу)** → «+» → **Add users** → пошта розробника → роль **Editor (Редактор)**; роль **Administrator** залиште лише акаунту коледжу та резервній особі.

### 3.7. Ввести ідентифікатор в адмінці сайту

Адміністратор сайту відкриває адмінку → група **SEO → Розмітка та аналітика** → поле ідентифікатора GA4 → вставляє `G-XXXXXXXXXX` → «Зберегти». Порожнє поле = аналітика вимкнена. До запуску поле заповнюється лише на основному сайті; на тестовому домені аналітика не працює.

### 3.8. Перевірка після запуску

1. Відкрийте https://otfk.od.ua у звичайному вікні браузера (не увійшовши в адмінку) → у банері натисніть **«Прийняти»**.
2. У GA4: **Reports → Realtime (Звіти → У реальному часі)** — за 1–2 хвилини має з'явитися 1 користувач.
3. Клацніть на сайті телефон, e-mail і будь-який документ — у Realtime мають з'явитися `click_phone`, `click_email`, `file_download`, **кожна по одному разу на клік**. Детальніше — **Admin → Data display → DebugView** (потрібне розширення браузера Google Analytics Debugger або допомога розробника).
4. Перевірте відмову: у підвалі сайту **«Налаштування cookies»** → «Відхилити» → оновіть сторінку → у Realtime нових подій від вас бути не повинно.
5. Дані у звичайних звітах з'являються із затримкою до 24–48 годин. Цифри GA4 завжди менші, ніж у Search Console і внутрішній статистиці сайту, бо враховують лише тих, хто погодився на cookies.

Довідка: [створення ресурсу GA4](https://support.google.com/analytics/answer/9304153?hl=uk), [покращене вимірювання](https://support.google.com/analytics/answer/9216061?hl=uk), [зберігання даних](https://support.google.com/analytics/answer/7667196?hl=uk), [Google signals](https://support.google.com/analytics/answer/9445345?hl=uk), [внутрішній трафік](https://support.google.com/analytics/answer/10104470?hl=uk), [ключові події](https://support.google.com/analytics/answer/9267568?hl=uk), [керування доступом](https://support.google.com/analytics/answer/9305788?hl=uk).

## 4. Коли що робити

| Коли | Що |
|---|---|
| **Зараз** (до кінця жовтня 2026) | Search Console: перевірити ресурс і доступи, підтвердити через DNS, додати розробника, вивантажити дані (1.1–1.4). Bing Webmaster Tools: імпорт (розділ 2). |
| **За 1–2 тижні до запуску** | Затвердити [політику конфіденційності](privacy-policy-draft.md) і опублікувати сторінку `/polityka-konfidentsiynosti`. Створити GA4 (3.1–3.6), передати `G-…` адміністратору сайту. |
| **У день запуску** | Ввести ID в адмінці (3.7), перевірити Realtime (3.8). Надіслати sitemap у Google і Bing, запросити індексацію пріоритетних сторінок (1.5). |
| **Тиждень 1** | Щодня: Search Console (Indexing → Pages), журнал 404 в адмінці. Позначити ключові події GA4 (3.5). |
| **Тижні 4, 8, 12** | Порівняти кліки, покази й CTR з вивантаженими даними (1.4) і тим самим періодом минулого року. |

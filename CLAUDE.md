## TL;DR проекта

Сайт Одесского технического фахового колледжа ОНТУ — **Laravel 12 + Filament 4** (не «чистый PHP»), Blade + Tailwind v4 + Alpine 3, Vite 7. Прод: MySQL на shared-хостинге ukraine.com.ua — **без Node и без queue-воркера**. Dev: SQLite, `php artisan serve --port=8002` (`.claude/launch.json`), тесты `composer test`. Статус — **PoC**: много демо-контента; всё временное учтено в разделе PoC-only в ARCHITECTURE.md. Роли админки `admin`/`editor` и базовая защита введены 06.10.2026 (`docs/security-audit.md`, `docs/admin-roadmap.md`, посібник персонала `docs/posibnyk-administratora.md`).

- Основной домен при замене старого сайта сохраняется: https://otfk.od.ua/ (уточнение пользователя 2026-10-07). SEO-план — docs/seo-plan.md; редиректы нужны только для изменённых URL, ресурс Search Console сохраняется.

- SEO-перенос планируется на октябрь–декабрь 2026 (резерв январь–февраль 2027); плановая смена приложения/путей/хостинга с марта по август запрещена по согласованному SEO-плану. Для `/uploads/` фото и зеркальные документы имеют разные назначения; карту строить по проверенным импортам и file_mirrors, не общим wildcard. Ход реализации — раздел «Статус реализации» в docs/seo-plan.md: этапы 1–3, минимальный этап 4 (`/en` + hreflang) и GA4 с баннером согласия в коде (PR #25 слит и развёрнут); карта старых URL импортирована на тестовом хостинге (4238 записей `legacy_redirects`). Осталось: переключение продакшена (перенос карты, проверка «принудительного HTTPS» панели), настоящий GA4 ID, утверждение политики конфиденциальности, замеры скорости.

## Конвенции кода (фактические, из существующего кода)

- Комментарии и docblocks — **на украинском**; публичный интерфейс использует `lang/uk/layout.php`, `lang/en/layout.php` и словари `public.php`/`feature.php` обеих локалей. Новые статические подписи выноси в словари; для Alpine используй `@js`, для дат/чисел — параметры перевода. Админка и служебные письма остаются украинскими.
- URL-слаги — транслит украинского: `/novyny`, `/spetsialnosti`, `/rozklad-dzvinkiv`. Новые роуты именовать так же.
- Отступы 4 пробела (2 для YAML), LF — `.editorconfig`. Форматтер `laravel/pint` установлен, но в CI не гоняется.
- Двуязычность: `SetPublicLocale` глобально определяет язык по `/en`, админка — `uk`; `App\Support\LocalizedUrl` формирует публичные ссылки с query/fragment (все публичные шаблоны, формы, поиск, RSS/ICS). Каркас переведён через `lang/`, меню — `label_en` в Filament → словарь стандартных подписей → оригинал; перевод вычисляется после общего кеша. `/en` индексируется автоматически при полном неустаревшем переводе (этап 4); Page/News поддерживают опциональные английские поля и отдельную публикацию, статический публичный UI переведён; на тестовой БД just-test.shop 2026-10-05 переведены и опубликованы все материалы (машинный перевод, нужна вычитка), новые материалы без перевода показываются по-украински; переключатель УКР/EN сохраняет материал, query и fragment. `LocalizedHtml::links()` меняет href материалов только при выводе, не в БД; файлы и внешние URL сохраняются. Подробности и оставшиеся этапы — ARCHITECTURE.md. Для новых ссылок публичной части используй этот механизм.
- Переводы Page/News: `HasEnglishTranslation::localized()` применяется только при публичном выводе; исходные атрибуты не локализовать (Filament/Telegram используют оригинал). `translation_published` требует title_en и body_en при непустом исходном body; без полного опубликованного перевода — целиком украинский материал. Хеш оригинала обновляется при изменении полного перевода/включении публикации, но не при изменении оригинала или счётчиков. Английский HTML в Filament — Textarea для сохранения разметки. Миграция полей не заполняет контент; поиск/подсказки на `/en` используют `searchPublic()` по опубликованным полным title_en/excerpt_en/body_en, иначе по оригинальному title; украинский поиск остаётся по title. Черновики/скрытые/будущие материалы исключены; переводы остальных сущностей описаны ниже, остаются редакторская приёмка и SEO.
- Переводы Specialty/Department/Program используют общий `HasEnglishTranslation` с модельными списками полей; публикация требует перевода всех заполненных текстовых полей оригинала. У Specialty переводятся также short_description/degree/study_form/duration. Новое заполненное поле оригинала без английского эквивалента возвращает цельный украинский fallback, сохраняя флаг и хеш. Формы/квиз должны загружать поля для проверки полноты; `localized()` применяется только публично, коды/slug/файлы и исходные атрибуты общие. Поиск специальностей на `/en` использует `searchPublic()`.
- Переводы FAQ/Event/NewsCategory используют тот же механизм: главное поле FAQ — question, обязательна также answer при заполненном оригинале; Event требует title и перевода заполненных description/location, категория — title. Публичный вывод и JSON-LD, календари ICS/Google и существующие подсказки событий используют опубликованный полный перевод с цельным fallback. Ответы FAQ и описания событий — обычный текст; JSON-LD FAQ/событий экранирует теги через JSON_HEX_TAG. Видимость, ID, slug, даты и URL общие; FAQ/категории не добавлены в поиск, события остаются только в подсказках.
- Переводы Staff/QuizQuestion/QuizOption: главные поля full_name/question/label; у Staff обязательны переводы всех заполненных position/academic_degree/bio. Инициалы и alt фото локализуются только публично; контакты/фото общие, bio как прежде не выводится в карточках. Каждый вопрос и вариант квиза имеет собственную публикацию/хеш; `QuizQuestion::publicPayload()` выбирает английский для всей группы только при полном опубликованном переводе вопроса и всех вариантов. Контроллер eager-load загружает все поля вариантов, сериализация — `@js`, баллы и связи общие. Новые/неполные/черновые варианты возвращают всю группу к украинскому оригиналу; состояние варианта видно в его секции Filament, колонка вопроса описывает только вопрос.
- Переводы DocumentCategory/Document/Video/Gallery/Photo: категория — title, документ/видео/альбом — title/description, фото — caption; собственные публикация и хеш. Файлы документов и YouTube общие; description видео сохраняется, но не выводится в карточках. Поиск документов использует `searchPublic()`. Галерея использует `albumLocalized()`/`publicCaption()` для цельного языка альбома и всех непустых исходных подписей; пустые подписи не требуют перевода. Список галерей eager-load загружает фото; лайтбокс сериализует URL и подпись через `@js`. Колонка «Переклад альбому EN» описывает только альбом, состояния фото — в Repeater. Изображения, даты, порядок, slug и архивный стиль общие.
- Переводы Banner/QuickLink/StatItem: баннер — title/subtitle/image_alt/link_label (title необязателен, нужен перевод всех заполненных подписей и хотя бы один английский текст), плитка/партнёр — title/description, статистика — label; числа value общие. Alt баннера локализуется только публично. Setting переводит value только для brand_short/brand_name/footer_about/site_description/contact_address/work_hours/announcement_text/site_version_label с type text/textarea. `map()`/`get()` сохраняют оригиналы для служебных вызовов, `publicMap()`/`publicGet()` локализуют после общих кешей `settings.map`/`settings.translations` (600с); оба сбрасывать при SQL-правках настроек. Телефоны/email/URL/цвета/файлы/Telegram общие. Бренд/описание без опубликованного перевода используют английский словарь; прочие значения — оригинал. Пустой исходный текст скрывает оголошение/бейдж и абзац `footer_about` в футере даже при сохранённом переводе. Текст `/kontakty` берётся из опубликованной CMS-страницы со slug `kontakty`, без неё — из настроек. `documents.title`/`title_en` — TEXT. Публичные файловые ссылки в отдельных абзацах/списках и PDF-iframe проходят через `App\Support\FileCards::render()`; каталог документов и список ОПП страницы специальности используют общий `x-file-card` (карточки `/spetsialnosti` — без файлов, ссылки на якоря ОПП через `App\Support\ProgramAnchors`, только при выводе) (только при выводе, БД не меняется). Раздел публичной информации с `document_categories.page_id` (опубликованная непустая страница) показывает содержимое этой страницы вместо списка документов (`DocumentCategory::sectionPage()`); собственный URL такой страницы — 301 на раздел и исключён из sitemap. `FileCards` сохраняет ручную нумерацию оригинала («1)», «93.») в названии карточки. Раздел «Циклові комісії» на `/struktura` показывает вступление и файлы (рейтинговое оценивание) из CMS-страницы `ciklovi-komisiyi`. Лицензирование с маркером старого импорта восстанавливает вложенные native details через `Page::publicBody()`/`AccreditationContent`; обе локали и URL сохраняются. Хеш настройки включает key/type/value, group не влияет. JSON-LD организации экранирует теги; RSS language соответствует локали.
- Формы EnglishTranslation проверяют обязательные английские поля при первичной публикации или изменении любого поля перевода (включая SEO); сохранение только оригинала/служебных полей разрешено с прежними publication/hash, даже если новое исходное поле вызывает цельный fallback. Get и record берутся в контексте конкретной записи, включая Repeater. Абсолютные URL на корень без slash перед query/fragment локализуются по parsed scheme/host/port/base path; внешние origin и userinfo не меняются. Heritage-frame использует публичную локаль даты и английский бренд из publicGet/словаря; украинская подпись сохраняет config(app.name).
- Настройки в админке — страницы-формы группы «Налаштування» (`app/Filament/Pages/*Settings.php`, база `App\Filament\Support\SettingsFormPage`: ключи с типом в `keys()`, английское поле `<key>_en` для `Setting::TRANSLATABLE_KEYS`, заполненный перевод публикуется, очищенный снимается). Новый пользовательский ключ settings добавлять на подходящую страницу, а не только в «Розширені налаштування» (`SettingResource`). Порядок групп меню задан `navigationGroups()` в `AdminPanelProvider`; новую группу вносить туда же. Святкові теми — `App\Support\HolidayTheme` (+ `holiday_theme_until`, автовыключение по Europe/Kyiv), SVG-компоненты `x-holiday.*` с inline-стилями (их же рендерит превью админки; значки используют общий `motif`, приветствие — общий `greeting`, гірлянды содержат тематические подвески), частицы — ленивый чанк `resources/js/holiday.js`; новая тема требует приветствия `layout.holiday.<key>` в обеих локалях (тест `HolidayThemeTest`). Без эмодзи в декоре.
- Основной HTML-текст в админке (body Page/News, description Specialty/Department) — `App\Filament\Forms\Components\HtmlRichEditor`, не голый `RichEditor`: TipTap Filament 4 с переключателем «Візуально / HTML» в hint поля. Стандартный RichEditor 4 на сервере превращает HTML в документ TipTap уже при загрузке и сохраняет нормализованный HTML (теряются iframe, class/style, ширины таблиц, комментарии) — поэтому `RichEditorStateCast` заменён на `HtmlStateCast`: стан — HTML-строка как в БД, в HTML превращается только документ TipTap (массив) от правки в визуальном режиме (`documentToHtml()`: `cleanEditorHtml()` убирает служебную разметку TipTap — обёртку `detailsContent`, colgroup/min-width, colspan/rowspan="1", text-align: start; маркеры `<!--imported-from:…-->` дописываются из исходной записи); `saveFileAttachments()` работает только для документа. Клиент (view компонента): TipTap 3 шлёт `update` и при `setContent`, поэтому запись строки в стан идёт через `write()` с `shouldUpdateState = false` у richEditorFormComponent, возврат в визуальный режим — `setContent(..., { emitUpdate: false })`; правкой считается любое отличие документа от снимка `baseline` (нормализованный `getHTML()` сразу после загрузки текста в TipTap, без служебной разметки и пустых абзацев в конце) — клавиатура, панель, перетаскивание, изменение размера картинки; совпадающий документ (нормализация TipTap) откатывается к исходной строке. Обёртку и CodeMirror искать через `$el.closest('.otfk-html-rich-editor')` (`root()`, `code()`), не `$root`/`$refs`: из кнопки перемикача в hint они указывают на x-data обёртки поля Filament (так терялась синхронизация режимов); `rich()` возвращает данные TipTap только при наличии `getEditor` (до x-load `$data` отдаёт данные родителя). Картинки — `resizableImages()` (width/height + inline px) и плавающая панель `image` (кнопки «Мале/Середнє/Велике/Уся ширина» = ⅓/½/¾ колонки сайта 720 px, не больше ширины файла, или без размера; `setImageSize()` в `html-editor.js` сам обновляет `<img>`, т. к. узел с ручками не перечитывает width/height). Область текста в редакторе — колонкой 45rem по центру (как на сайте), фото без размера показывается компактно (max-height 16rem) с пометкой «на сайті — на всю ширину»; на сайте `.prose-site img[width]` уменьшается пропорционально (`height: auto !important`). Превʼю несохранённой формы берёт стан через `HtmlRichEditor::rawStateWithHtml()` (документ TipTap → HTML; иначе в превʼю попадал массив и выводилось «doc»). Для разметки, которую TipTap упрощает (`HtmlRichEditor::LOSSY`/`isLossy()`, паттерн общий для PHP/JS; details, таблицы и thead, картинки с размерами, вирівнювання, iframe — не lossy; `<a name>`, `details open`, srcset/sizes/download/lang/dir — lossy), — предупреждение и подтверждение первой правки. Картинка, загруженная в визуальном режиме и сохранённая уже из режима HTML (строка с `<img data-id>` временной загрузки), переносится в постоянное хранилище в `saveFileAttachments()` без нормализации остального HTML; снимок `baseline` ждёт TipTap без лимита; Ctrl/Cmd+S сначала сбрасывает отложенный набор CodeMirror; замена документа CodeMirror извне не попадает в историю отмены. Кавычки `"` внутри JS в `x-data` ломают атрибут — не использовать. Режим HTML — CodeMirror 6 (вход Vite `resources/js/admin/html-editor.js` через render-hook панели, ленивый чанк; фон `.cm-activeLine` в темах `html-editor-codemirror.js` — только полупрозрачный: слой выделения лежит под текстом, непрозрачный фон прятал выделение в строке курсора) с автоформатированием `resources/js/admin/html-format.js`: переносы только вокруг блочных тегов, текст/инлайн/pre/комментарии не трогать. Над кодом — кнопки «+ Розгортний блок» и «Розділи → розгортні блоки» (`resources/js/admin/html-sections.js`, тест `tests/Frontend/HtmlSectionsTest.mjs`; вложенность — выделить заголовок с блоками и нажать «+ Розгортний блок»). Панель визуального режима: H2–H4, выравнивание, списки, цитата, линия, таблица, розгортний блок, «PDF / відео», вложения (`getDefaultToolbarButtons()`). Кнопка «Розгортний блок» визуального режима — `wrapInDetails()` в `html-editor.js` (как `detailsSnippet()` режима HTML): заголовок в начале выделения (или первый абзац при нескольких выделенных блоках) становится подписью, остальное — содержимым; H2–H4 при курсоре в подписи блока (схема TipTap `detailsSummary` — только текст) разворачивают блок обратно — `heading()`: подпись → заголовок этого уровня, содержимое — под ним. Обработчики подменены в `HtmlRichEditor::getTools()` (без скрипта — стандартные команды Filament). Кнопка «PDF / відео» — плагин `App\Filament\Forms\Components\RichEditor\EmbedPlugin`: модальное окно (ссылка или загрузка PDF в `storage/app/public/documents/vbudovani`, название), адрес нормализует `App\Support\EmbedSource` (youtu.be/watch/shorts → `youtube.com/embed/ID?start=`, Drive/Docs → `/preview`, карта — только адрес вбудовування, свой сайт → относительный путь, итог проверяет `IframeSourceSanitizer::allowed()`), вставляется `<iframe>` с атрибутами импорта (`class="w-full" style="min-height:24rem;border:0" loading="lazy"`, для видео ещё allow/allowfullscreen/referrerpolicy). Узел TipTap `embed` — пара `EmbedExtension` (PHP) и `public/js/admin/rich-editor-embed.js` (статический ES-модуль, без сборки; берёт TipTap из `window.FilamentRichEditor.tiptap`, в редакторе показывает карточку без загрузки iframe) с общим списком атрибутов; существующие iframe открываются в визуальном режиме без потерь (обёртка `<p>` вокруг них исчезает — FileCards обрабатывает оба вида). - Восстановление после старой drop-миграции: `2026_10_04_175000` создаёт только отсутствующие testimonials/applicant_requests/feedback_messages без наполнения; down не удаляет таблицы. Не удалять журнал migrations и не откатывать старые контент-миграции для ремонта схемы.
- Контент-фикстуры — идемпотентные data-миграции (`firstOrCreate`, guard-проверки, `down()` не удаляет контент).
- Тесты — PHPUnit Feature-тесты, фиксируют поведенческие контракты; на каждую фичу — тест в `tests/Feature/`.

## Жёсткие правила «не трогать»

- **Не переводить джобы на `ShouldQueue`** — на хостинге нет воркера; `afterResponse()` — осознанное решение (DEPLOY.md).
- **Не возвращать тёмную тему / theme-toggle** — light-only закреплён тестом `FrontendPolishTest::test_site_is_light_only_without_theme_toggle`.
- **Не менять `'timezone' => 'UTC'`** в `config/app.php` без сквозной ревизии: даты хранятся как киевское wall-clock и вручную шифтуются в 5 местах (см. Gotcha «Таймзона»).
- **Catch-all `/{page:slug}`** находится в конце `routes/public.php`, украинская регистрация остаётся последней в `routes/web.php`; новый top-level путь → добавить в регексп исключений в той же правке.
- **Не запускать `db:seed` / `SiteSeeder` на окружении с реальным контентом** — сидер деструктивен (delete меню, персонала, видео, баннеров).
- **`public/build/` в git не коммитить** (он в `.gitignore`) — прод-бандл собирает деплой-workflow `deploy.yml` и заливает rsync-ом. Локально для проверки — `npm run build` или `npm run dev`.
- **Деплой и ветки:** с 2026-10-09 `master` — продакшен, `test` — тестовая ветка (ветка `prod` упразднена). Push в `master` = сборка и публикация ветки `plesk-build` (`master` + `public/build`), которую разворачивает Laravel Toolkit на Plesk-поддомене `new.otfk.od.ua` (вебхук `PLESK_DEPLOY_WEBHOOK`); push в `test` (и ручной запуск из любой ветки, кроме `master`) = SSH-автодеплой на тестовый хостинг just-test.shop (`.github/workflows/deploy.yml`). Задачи — в своих ветках, слияние сначала в `test` с проверкой на just-test.shop, выпуск — перенос `test` в `master`. В `plesk-build` руками не коммитить. Не пушить в `test`/`master` без явной просьбы пользователя (правило «не коммитить/не пушить» теперь ещё и деплоит). SSH на Plesk — chroot с PHP 7.2, пользователь его не меняет: artisan-команды там — через вкладку «Виконавець» Toolkit, не SSH; сценарий развёртывания Toolkit вызывает `/opt/plesk/php/8.3/bin/php artisan …` (голый `php` там 7.2); приложение — `new.otfk.od.ua/public`, веб-корень — `new.otfk.od.ua/public/public`, файлы — `new.otfk.od.ua/public/storage/app/public` (FTP подписки открывается в `httpdocs` старого сайта — относительные пути уводят туда); `SEO_PRIMARY_HOST` на поддомен не менять (поддомен должен оставаться noindex). Настройка — DEPLOY.md «Plesk: new.otfk.od.ua».
- **`ARCHITECTURE.html` и прочие HTML-твины руками не редактировать** — только `node DocsHtml/generate.mjs`.
- Слаг `istoriya` (drop cap) и страница `abituriyentu` (7 хардкод-ссылок) — не переименовывать без правки шаблонов и тестов.

## Карта работы и проверки

- Публичные страницы: `routes/web.php` → общая карта `routes/public.php` (украинские имена и `/en` с именами `en.*`) → `app/Http/Controllers/` → `app/Models/` → `resources/views/`. Общий layout — `resources/views/components/layouts/app.blade.php`.
- Админка: `app/Filament/Resources/`, `Pages/`, `Widgets/`; настройка панели — `app/Providers/Filament/AdminPanelProvider.php`.
- Схема и контент: `database/migrations/`; внешние интеграции — `app/Services/`, `app/Observers/`, `app/Jobs/`, `app/Mail/`.
- Локальный сервер: `php artisan serve --port=8002`. `composer run dev` дополнительно запускает очередь, pail и Vite; это dev-скрипт, а не описание прод-инфраструктуры.
- Локальный PHP должен быть 8.3, как в CI и на хостинге: на PHP 8.5 `parse_url()` портит не-ASCII байты, и около 12 тестов с кириллицей в URL падают (поиск, `legacy_redirects`, `file_mirrors`) — это не баг кода.
- PHP: `composer test`; точечная проверка — `php artisan test --filter=ИмяТеста`. `phpunit.xml` задаёт memory_limit=512M для расширенного набора тестов, `APP_URL=http://localhost` (тесты ждут URL без порта, локальный `.env` с `:8002` не должен влиять), SQLite `:memory:`, mail/cache/session в памяти и синхронную очередь. `tests/TestCase.php` включает сидирование и отключает Vite, поэтому PHP-тесты не проверяют сборку фронтенда. До запуска убедись, что окружение тестовое и нет закэшированного production-конфига.
- Фронтенд: `npm run build`; частицы праздничных тем — `node --test tests/Frontend/HolidayParticlesTest.mjs`, аналитика — `node --test tests/Frontend/AnalyticsTest.mjs`, форматирование HTML редактора — `node --test tests/Frontend/HtmlFormatTest.mjs` (каталог целиком node не принимает; CI node-тесты не гоняет) (60/120 Гц, reduced motion, отсутствие canvas, однократный показ и очистка). Воспроизводимая установка из lock-файла — `npm ci`. Для PHP используй `composer install`, без незапрошенного обновления зависимостей.
- Документация: проверь локальные ссылки и `git diff --check`; при изменении `ARCHITECTURE.md` обязательно запусти `node DocsHtml/generate.mjs`. Для правок только документации PHP-тесты и сборка фронтенда не обязательны.
- `.claude/launch.json` задаёт запуск сервера; `.claude/settings.json` содержит shell-hooks для защиты и регенерации HTML архитектуры. Hooks используют POSIX shell и `/usr/bin/python3`; их работу в Windows нельзя считать проверенной. Codex выполняет эти правила из `AGENTS.md`, не полагаясь на Claude hooks.

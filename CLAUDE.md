## TL;DR проекта

Сайт Одесского технического фахового колледжа ОНТУ — **Laravel 12 + Filament 3** (не «чистый PHP»), Blade + Tailwind v4 + Alpine 3, Vite 7. Прод: MySQL на shared-хостинге ukraine.com.ua — **без Node и без queue-воркера**. Dev: SQLite, `php artisan serve --port=8002` (`.claude/launch.json`), тесты `composer test`. Статус — **PoC**: много демо-контента; всё временное учтено в разделе PoC-only в ARCHITECTURE.md. Роли админки `admin`/`editor` и базовая защита введены 06.10.2026 (`docs/security-audit.md`, `docs/admin-roadmap.md`, посібник персонала `docs/posibnyk-administratora.md`).

## Конвенции кода (фактические, из существующего кода)

- Комментарии и docblocks — **на украинском**; публичный интерфейс использует `lang/uk/layout.php`, `lang/en/layout.php` и словари `public.php`/`feature.php` обеих локалей. Новые статические подписи выноси в словари; для Alpine используй `@js`, для дат/чисел — параметры перевода. Админка и служебные письма остаются украинскими.
- URL-слаги — транслит украинского: `/novyny`, `/spetsialnosti`, `/rozklad-dzvinkiv`. Новые роуты именовать так же.
- Отступы 4 пробела (2 для YAML), LF — `.editorconfig`. Форматтер `laravel/pint` установлен, но в CI не гоняется.
- Двуязычность: `SetPublicLocale` глобально определяет язык по `/en`, админка — `uk`; `App\Support\LocalizedUrl` формирует публичные ссылки с query/fragment (все публичные шаблоны, формы, поиск, RSS/ICS). Каркас переведён через `lang/`, меню — `label_en` в Filament → словарь стандартных подписей → оригинал; перевод вычисляется после общего кеша. `/en` временно имеет `noindex`; Page/News поддерживают опциональные английские поля и отдельную публикацию, статический публичный UI переведён; на тестовой БД just-test.shop 2026-10-05 переведены и опубликованы все материалы (машинный перевод, нужна вычитка), новые материалы без перевода показываются по-украински; переключатель УКР/EN сохраняет материал, query и fragment. `LocalizedHtml::links()` меняет href материалов только при выводе, не в БД; файлы и внешние URL сохраняются. Подробности и оставшиеся этапы — ARCHITECTURE.md. Для новых ссылок публичной части используй этот механизм.
- Переводы Page/News: `HasEnglishTranslation::localized()` применяется только при публичном выводе; исходные атрибуты не локализовать (Filament/Telegram используют оригинал). `translation_published` требует title_en и body_en при непустом исходном body; без полного опубликованного перевода — целиком украинский материал. Хеш оригинала обновляется при изменении полного перевода/включении публикации, но не при изменении оригинала или счётчиков. Английский HTML в Filament — Textarea для сохранения разметки. Миграция полей не заполняет контент; поиск/подсказки на `/en` используют `searchPublic()` по опубликованным полным title_en/excerpt_en/body_en, иначе по оригинальному title; украинский поиск остаётся по title. Черновики/скрытые/будущие материалы исключены; SEO и перевод остальных сущностей пока следующий этап.
- Переводы Specialty/Department/Program используют общий `HasEnglishTranslation` с модельными списками полей; публикация требует перевода всех заполненных текстовых полей оригинала. У Specialty переводятся также short_description/degree/study_form/duration. Новое заполненное поле оригинала без английского эквивалента возвращает цельный украинский fallback, сохраняя флаг и хеш. Формы/квиз должны загружать поля для проверки полноты; `localized()` применяется только публично, коды/slug/файлы и исходные атрибуты общие. Поиск специальностей на `/en` использует `searchPublic()`.
- Переводы FAQ/Event/NewsCategory используют тот же механизм: главное поле FAQ — question, обязательна также answer при заполненном оригинале; Event требует title и перевода заполненных description/location, категория — title. Публичный вывод и JSON-LD, календари ICS/Google и существующие подсказки событий используют опубликованный полный перевод с цельным fallback. Ответы FAQ и описания событий — обычный текст; JSON-LD FAQ/событий экранирует теги через JSON_HEX_TAG. Видимость, ID, slug, даты и URL общие; FAQ/категории не добавлены в поиск, события остаются только в подсказках.
- Переводы Staff/QuizQuestion/QuizOption: главные поля full_name/question/label; у Staff обязательны переводы всех заполненных position/academic_degree/bio. Инициалы и alt фото локализуются только публично; контакты/фото общие, bio как прежде не выводится в карточках. Каждый вопрос и вариант квиза имеет собственную публикацию/хеш; `QuizQuestion::publicPayload()` выбирает английский для всей группы только при полном опубликованном переводе вопроса и всех вариантов. Контроллер eager-load загружает все поля вариантов, сериализация — `@js`, баллы и связи общие. Новые/неполные/черновые варианты возвращают всю группу к украинскому оригиналу; состояние варианта видно в его секции Filament, колонка вопроса описывает только вопрос.
- Переводы DocumentCategory/Document/Video/Gallery/Photo: категория — title, документ/видео/альбом — title/description, фото — caption; собственные публикация и хеш. Файлы документов и YouTube общие; description видео сохраняется, но не выводится в карточках. Поиск документов использует `searchPublic()`. Галерея использует `albumLocalized()`/`publicCaption()` для цельного языка альбома и всех непустых исходных подписей; пустые подписи не требуют перевода. Список галерей eager-load загружает фото; лайтбокс сериализует URL и подпись через `@js`. Колонка «Переклад альбому EN» описывает только альбом, состояния фото — в Repeater. Изображения, даты, порядок, slug и архивный стиль общие.
- Переводы Banner/QuickLink/StatItem: баннер — title/subtitle/image_alt/link_label (title необязателен, нужен перевод всех заполненных подписей и хотя бы один английский текст), плитка/партнёр — title/description, статистика — label; числа value общие. Alt баннера локализуется только публично. Setting переводит value только для brand_short/brand_name/footer_about/site_description/contact_address/work_hours/announcement_text/site_version_label с type text/textarea. `map()`/`get()` сохраняют оригиналы для служебных вызовов, `publicMap()`/`publicGet()` локализуют после общих кешей `settings.map`/`settings.translations` (600с); оба сбрасывать при SQL-правках настроек. Телефоны/email/URL/цвета/файлы/Telegram общие. Бренд/описание без опубликованного перевода используют английский словарь; прочие значения — оригинал. Пустой исходный текст скрывает оголошение/бейдж и абзац `footer_about` в футере даже при сохранённом переводе. Текст `/kontakty` берётся из опубликованной CMS-страницы со slug `kontakty`, без неё — из настроек. `documents.title`/`title_en` — TEXT. Публичные файловые ссылки в отдельных абзацах/списках и PDF-iframe проходят через `App\Support\FileCards::render()`; каталог документов и программы специальностей используют общий `x-file-card` (только при выводе, БД не меняется). Лицензирование с маркером старого импорта восстанавливает вложенные native details через `Page::publicBody()`/`AccreditationContent`; обе локали и URL сохраняются. Хеш настройки включает key/type/value, group не влияет. JSON-LD организации экранирует теги; RSS language соответствует локали.
- Формы EnglishTranslation проверяют обязательные английские поля при первичной публикации или изменении любого поля перевода (включая SEO); сохранение только оригинала/служебных полей разрешено с прежними publication/hash, даже если новое исходное поле вызывает цельный fallback. Get и record берутся в контексте конкретной записи, включая Repeater. Абсолютные URL на корень без slash перед query/fragment локализуются по parsed scheme/host/port/base path; внешние origin и userinfo не меняются. Heritage-frame использует публичную локаль даты и английский бренд из publicGet/словаря; украинская подпись сохраняет config(app.name).
- Настройки в админке — страницы-формы группы «Налаштування» (`app/Filament/Pages/*Settings.php`, база `App\Filament\Support\SettingsFormPage`: ключи с типом в `keys()`, английское поле `<key>_en` для `Setting::TRANSLATABLE_KEYS`, заполненный перевод публикуется, очищенный снимается). Новый пользовательский ключ settings добавлять на подходящую страницу, а не только в «Розширені налаштування» (`SettingResource`). Порядок групп меню задан `navigationGroups()` в `AdminPanelProvider`; новую группу вносить туда же. Святкові теми — `App\Support\HolidayTheme` (+ `holiday_theme_until`, автовыключение по Europe/Kyiv), SVG-компоненты `x-holiday.*` с inline-стилями (их же рендерит превью админки; значки используют общий `motif`, приветствие — общий `greeting`, гірлянды содержат тематические подвески), частицы — ленивый чанк `resources/js/holiday.js`; новая тема требует приветствия `layout.holiday.<key>` в обеих локалях (тест `HolidayThemeTest`). Без эмодзи в декоре.

- Расписание звонков: две смены shift 1/2; `BellPeriod::active()` сортирует shift/starts/id, кеш `bell_periods.v3` сбрасывается при saved/deleted. Live-подсветка по ID показывает все одновременные пары; перерывы считаются внутри смены после максимального конца предыдущих интервалов. Админская страница `BellSchedule` редактирует 4 пары каждой смены и флаги `bells_second_shift`/`bells_now_chip`; не возвращать единый список без группировки.
- Таблицы публичного HTML оборачивать `ResponsiveTables::render()` при выводе, после локализации ссылок; исходный HTML в БД не переписывать. Прокрутка — на `.content-table-scroll` с `contain:inline-size`, сама таблица — `display:table` и полная ширина; `display:block` на таблицу не возвращать.
- Контроллеры публичной части тонкие; списки — через модельные scopes (`published`, `ordered`, `active`, `visible`). Автослаг — в `booted()`/`saving` моделей.
- Безопасность админки (контракты `AdminRolesTest`/`AdminSecurityTest`/`AdminExposureTest`): роли `users.role` = `admin`|`editor` (`User::ROLES`, `isAdmin()`); «Користувачі», «Розширені налаштування», «Меню навігації» и все страницы-наследники `SettingsFormPage` — только `admin` через `canAccess()` + политики-наследники `App\Policies\AdminOnlyPolicy` (авто-обнаружение по имени модели) + повторный `abort_unless(static::canAccess(), 403)` в Livewire-действиях (`save()`, `sendTest()`). Новый ресурс/страница — сразу решить роль и добавить тест; контент доступен редактору. `User::booted()` запрещает удалить себя/последнего `admin`, понизить последнего `admin`, неизвестную роль; массовое удаление пользователей выключено. `UserFactory` создаёт `admin` по умолчанию, `->editor()` — редактора; `DatabaseSeeder` требует `ADMIN_PASSWORD` вне `local`/`testing` и не перезаписывает пароль (`firstOrCreate`).
- Загрузки: `config/livewire.php` задаёт для всех временных загрузок `extensions:` + `mimetypes:` (jpg/png/gif/webp/pdf/doc(x)/xls(x)/ppt(x)/odt/ods/odp, SVG/HTML/PHP отклоняются) + `max:20480`; новый `FileUpload` — `acceptedFileTypes` + `maxSize` в пределах этого списка. `storage/app/public/.htaccess` (в git через `!.htaccess`) запрещает исполнение скриптов и ставит CSP `sandbox` на HTML/SVG/JS — не удалять и не ослаблять. HTML редактора — каст `App\Casts\SafeHtml` (`HtmlSanitizer` на `symfony/html-sanitizer`: DOM-парсер с белым списком, iframe только по `IframeSourceSanitizer` — YouTube/Google Maps/Docs/Drive/свой сайт; маркеры `<!--imported-from:…-->` сохраняются отдельно; не возвращать regex-вариант — тест `AdminSecurityTest` содержит его обходы) на `body`/`body_en` Page/News, `description`/`description_en` Specialty/Department, `bio`/`bio_en` Staff; новое HTML-поле — тот же каст; санитайзер нормализует разметку при сохранении (`<tbody>`, `<img />`, кавычки атрибутов), поэтому тесты сравнивают сохранённый HTML с нормализованным ожиданием, а не с исходной строкой; любой `json_encode` внутри `<script>` — с `JSON_HEX_TAG`; поля ссылок — правило `App\Rules\SafeUrl`. `SecurityHeaders` стоит и в стеке панели (`frame-ancestors 'self'`, `X-Robots-Tag: noindex` для `/admin*`/`/livewire/*`); публичной ссылки на `/admin` нет. Политика паролей — `Password::defaults()` (12+, буквы и цифры, в production `uncompromised()`). Журнал входов — слушатель `App\Listeners\LogAuthenticationEvents` (login/failed/logout) и `App\Filament\Auth\Login::getRateLimitedNotification()` (lockout; Filament не шлёт событие `Lockout`; класс вне `Filament/Pages`, чтобы не попасть в auto-discovery) → канал `security` (`storage/logs/security-*.log`, 90 дней) и `users.last_login_at/ip`. `User::$attributes` задаёт роль `editor` по умолчанию; удаление в `UserResource` проходит через `guardDeletion()` (уведомление вместо исключения). В тестах `TestCase::setUp()` сбрасывает `Paginator::useTailwind()` — `Livewire::test()` таблицы с 403 на mount не восстанавливает статический вид пагинации. `composer audit --locked` в CI блокирующий, `composer.json` фиксирует `platform.php = 8.3.0`: обновлять зависимости патч/минор без `Downgrading`, шаг аудита не отключать. `deploy.yml` сам гоняет тесты и аудит (job `tests`, `needs`) и ставит на сервер `${{ github.sha }}` (`git fetch origin <sha>`, работает и для ручного запуска с другой ветки) — не возвращать `origin/master`. Запрет скриптов в `/storage/` продублирован `RewriteRule … [F]` в `public/.htaccess`. `style` проходит `StyleAttributeSanitizer` (белый список CSS-свойств), `class` — `ClassAttributeSanitizer` (без утилит fixed/absolute/inset/z/opacity/translate/w-screen и т.п.; новые публичные утилиты-оверлеи добавлять в его блок-лист). Старый HTML чистится только командой `otfk:sanitize-content` (dry-run → `--apply`: сначала бэкап с проверкой, потом запись; без Telegram), не массовым пересохранением.

CMS-страницу `/zvorotniy-zvyazok` со ссылками обратной связи сохранять; архивные таблицы applicant_requests/feedback_messages/testimonials не удалять (нужны для истории и старых миграций). В контент вставлять только относительный `FileMirror::publicUrl()` (`/storage/mirror/...`), не абсолютный домен хостинга. Без cron на хостинге очередь запускается workflow `mirror-files.yml` (`gh workflow run mirror-files.yml -f limit=500`). Переезд хостинга: `otfk:backup` + `otfk:storage-export` → `otfk:storage-import` (sha256, без удаления) → `otfk:mirror-files --verify [--from=https://старый-хост]` — пошагово в DEPLOY.md. Описания опций artisan-команд не должны содержать `{...}` (Laravel принимает их за аргументы).

Миграция перевода `180000` повторяется после частичного MySQL DDL, добавляя только отсутствующие поля; существующие записи/переводы сохраняются. Не удалять журнал migrations и не откатывать старые контент-миграции для ремонта схемы.
- Контент-фикстуры — идемпотентные data-миграции (`firstOrCreate`, guard-проверки, `down()` не удаляет контент).
- Тесты — PHPUnit Feature-тесты, фиксируют поведенческие контракты; на каждую фичу — тест в `tests/Feature/`.

## Жёсткие правила «не трогать»

- **Не переводить джобы на `ShouldQueue`** — на хостинге нет воркера; `afterResponse()` — осознанное решение (DEPLOY.md).
- **Не возвращать тёмную тему / theme-toggle** — light-only закреплён тестом `FrontendPolishTest::test_site_is_light_only_without_theme_toggle`.
- **Не менять `'timezone' => 'UTC'`** в `config/app.php` без сквозной ревизии: даты хранятся как киевское wall-clock и вручную шифтуются в 5 местах (см. Gotcha «Таймзона»).
- **Catch-all `/{page:slug}`** находится в конце `routes/public.php`, украинская регистрация остаётся последней в `routes/web.php`; новый top-level путь → добавить в регексп исключений в той же правке.
- **Не запускать `db:seed` / `SiteSeeder` на окружении с реальным контентом** — сидер деструктивен (delete меню, персонала, видео, баннеров).
- **`public/build/` в git не коммитить** (он в `.gitignore`) — прод-бандл собирает деплой-workflow `deploy.yml` и заливает rsync-ом. Локально для проверки — `npm run build` или `npm run dev`.

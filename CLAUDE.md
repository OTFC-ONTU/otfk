# CLAUDE.md — рабочие правила проекта otfk

## Порядок чтения для новой задачи

1. Инструкции своего агента: `CLAUDE.md` для Claude, `AGENTS.md` для Codex. Общая часть этих файлов должна совпадать; перед работой проверь также файл другого агента.
2. [ARCHITECTURE.md](ARCHITECTURE.md) — полный справочник: карта маршрутов, схема БД, CI/деплой, **Gotchas** и **PoC-only**. Перед правкой любого маршрута, миграции или workflow — обязателен.
3. Затем — код. При конфликте доков и кода **побеждает код** (и это повод исправить доки).

## TL;DR проекта

Сайт Одесского технического фахового колледжа ОНТУ — **Laravel 12 + Filament 3** (не «чистый PHP»), Blade + Tailwind v4 + Alpine 3, Vite 7. Прод: MySQL на shared-хостинге ukraine.com.ua — **без Node и без queue-воркера**. Dev: SQLite, `php artisan serve --port=8002` (`.claude/launch.json`), тесты `composer test`. Статус — **PoC**: ролей нет, много демо-контента; всё временное учтено в разделе PoC-only в ARCHITECTURE.md.

## Конвенции кода (фактические, из существующего кода)

- Комментарии и docblocks — **на украинском**; публичный интерфейс использует `lang/uk/layout.php`, `lang/en/layout.php` и словари `public.php` обеих локалей. Новые статические подписи выноси в словари; для Alpine используй `@js`, для дат/чисел — параметры перевода. Админка и служебные письма остаются украинскими.
- URL-слаги — транслит украинского: `/novyny`, `/spetsialnosti`, `/rozklad-dzvinkiv`. Новые роуты именовать так же.
- Отступы 4 пробела (2 для YAML), LF — `.editorconfig`. Форматтер `laravel/pint` установлен, но в CI не гоняется.
- Двуязычность: `SetPublicLocale` глобально определяет язык по `/en`, админка — `uk`; `App\Support\LocalizedUrl` формирует публичные ссылки с query/fragment (все публичные шаблоны, формы, поиск, RSS/ICS). Каркас переведён через `lang/`, меню — `label_en` в Filament → словарь стандартных подписей → оригинал; перевод вычисляется после общего кеша. `/en` временно имеет `noindex`; Page/News поддерживают опциональные английские поля и отдельную публикацию, статический публичный UI переведён; на тестовой БД just-test.shop 2026-10-05 переведены и опубликованы все материалы (машинный перевод, нужна вычитка), новые материалы без перевода показываются по-украински; переключатель УКР/EN сохраняет материал, query и fragment. `LocalizedHtml::links()` меняет href материалов только при выводе, не в БД; файлы и внешние URL сохраняются. Подробности и оставшиеся этапы — ARCHITECTURE.md. Для новых ссылок публичной части используй этот механизм.
- Переводы Page/News: `HasEnglishTranslation::localized()` применяется только при публичном выводе; исходные атрибуты не локализовать (Filament/Telegram используют оригинал). `translation_published` требует title_en и body_en при непустом исходном body; без полного опубликованного перевода — целиком украинский материал. Хеш оригинала обновляется при изменении полного перевода/включении публикации, но не при изменении оригинала или счётчиков. Английский HTML в Filament — Textarea для сохранения разметки. Миграция полей не заполняет контент; поиск/подсказки на `/en` используют `searchPublic()` по опубликованным полным title_en/excerpt_en/body_en, иначе по оригинальному title; украинский поиск остаётся по title. Черновики/скрытые/будущие материалы исключены; SEO и перевод остальных сущностей пока следующий этап.
- Переводы Specialty/Department/Program используют общий `HasEnglishTranslation` с модельными списками полей; публикация требует перевода всех заполненных текстовых полей оригинала. У Specialty переводятся также short_description/degree/study_form/duration. Новое заполненное поле оригинала без английского эквивалента возвращает цельный украинский fallback, сохраняя флаг и хеш. Формы/квиз должны загружать поля для проверки полноты; `localized()` применяется только публично, коды/slug/файлы и исходные атрибуты общие. Поиск специальностей на `/en` использует `searchPublic()`.
- Переводы FAQ/Event/NewsCategory используют тот же механизм: главное поле FAQ — question, обязательна также answer при заполненном оригинале; Event требует title и перевода заполненных description/location, категория — title. Публичный вывод и JSON-LD, календари ICS/Google и существующие подсказки событий используют опубликованный полный перевод с цельным fallback. Ответы FAQ и описания событий — обычный текст; JSON-LD FAQ/событий экранирует теги через JSON_HEX_TAG. Видимость, ID, slug, даты и URL общие; FAQ/категории не добавлены в поиск, события остаются только в подсказках.
- Переводы Staff/QuizQuestion/QuizOption: главные поля full_name/question/label; у Staff обязательны переводы всех заполненных position/academic_degree/bio. Инициалы и alt фото локализуются только публично; контакты/фото общие, bio как прежде не выводится в карточках. Каждый вопрос и вариант квиза имеет собственную публикацию/хеш; `QuizQuestion::publicPayload()` выбирает английский для всей группы только при полном опубликованном переводе вопроса и всех вариантов. Контроллер eager-load загружает все поля вариантов, сериализация — `@js`, баллы и связи общие. Новые/неполные/черновые варианты возвращают всю группу к украинскому оригиналу; состояние варианта видно в его секции Filament, колонка вопроса описывает только вопрос.
- Переводы DocumentCategory/Document/Video/Gallery/Photo: категория — title, документ/видео/альбом — title/description, фото — caption; собственные публикация и хеш. Файлы документов и YouTube общие; description видео сохраняется, но не выводится в карточках. Поиск документов использует `searchPublic()`. Галерея использует `albumLocalized()`/`publicCaption()` для цельного языка альбома и всех непустых исходных подписей; пустые подписи не требуют перевода. Список галерей eager-load загружает фото; лайтбокс сериализует URL и подпись через `@js`. Колонка «Переклад альбому EN» описывает только альбом, состояния фото — в Repeater. Изображения, даты, порядок, slug и архивный стиль общие.
- Переводы Banner/QuickLink/Testimonial/StatItem: баннер — title/subtitle/image_alt/link_label (title необязателен, нужен перевод всех заполненных подписей и хотя бы один английский текст), плитка/партнёр — title/description, отзыв — name/role/quote, статистика — label; числа value общие. Alt баннера, имя/alt/инициалы отзыва локализуются только публично. Setting переводит value только для brand_short/brand_name/footer_about/site_description/contact_address/work_hours/announcement_text/site_version_label с type text/textarea. `map()`/`get()` сохраняют оригиналы для служебных вызовов, `publicMap()`/`publicGet()` локализуют после общих кешей `settings.map`/`settings.translations` (600с); оба сбрасывать при SQL-правках настроек. Телефоны/email/URL/цвета/файлы/Telegram общие. Бренд/описание без опубликованного перевода используют английский словарь; прочие значения — оригинал. Пустой исходный текст скрывает оголошение/бейдж даже при сохранённом переводе. Хеш настройки включает key/type/value, group не влияет. JSON-LD организации экранирует теги; RSS language соответствует локали.
- Формы EnglishTranslation проверяют обязательные английские поля при первичной публикации или изменении любого поля перевода (включая SEO); сохранение только оригинала/служебных полей разрешено с прежними publication/hash, даже если новое исходное поле вызывает цельный fallback. Get и record берутся в контексте конкретной записи, включая Repeater. Абсолютные URL на корень без slash перед query/fragment локализуются по parsed scheme/host/port/base path; внешние origin и userinfo не меняются. Heritage-frame использует публичную локаль даты и английский бренд из publicGet/словаря; украинская подпись сохраняет config(app.name).
- Контроллеры публичной части тонкие; списки — через модельные scopes (`published`, `ordered`, `active`, `visible`). Автослаг — в `booted()`/`saving` моделей.
- Админка — только Filament Resources (auto-discovery), ручных админ-роутов не писать.
- Файлы старого сайта на хостинг попадают только через очередь `file_mirrors` (`FileMirror::enqueue()`, планировщик запускает `otfk:mirror-files` каждую минуту; хосты — `FILE_MIRROR_HOSTS`, белый список расширений, проверка сигнатуры). В контент вставлять только относительный `FileMirror::publicUrl()` (`/storage/mirror/...`), не абсолютный домен хостинга. Переезд хостинга: `otfk:backup` + `otfk:storage-export` → `otfk:storage-import` (sha256, без удаления) → `otfk:mirror-files --verify [--from=https://старый-хост]` — пошагово в DEPLOY.md. Описания опций artisan-команд не должны содержать `{...}` (Laravel принимает их за аргументы).
- Фоновое — только `dispatch(...)->afterResponse()`. Кэш точечный: `Setting::map()`/`settings.translations`, `MenuItem::navigation()`, `BellPeriod::active()` по 600с, со сбросом в `booted()`.
- Восстановление после старой drop-миграции: `2026_10_04_175000` создаёт только отсутствующие testimonials/applicant_requests/feedback_messages без наполнения; down не удаляет таблицы. Миграция перевода `180000` повторяется после частичного MySQL DDL, добавляя только отсутствующие поля; существующие записи/переводы сохраняются. Не удалять журнал migrations и не откатывать старые контент-миграции для ремонта схемы.
- Контент-фикстуры — идемпотентные data-миграции (`firstOrCreate`, guard-проверки, `down()` не удаляет контент).
- Тесты — PHPUnit Feature-тесты, фиксируют поведенческие контракты; на каждую фичу — тест в `tests/Feature/`.

## Жёсткие правила «не трогать»

- **Не переводить джобы на `ShouldQueue`** — на хостинге нет воркера; `afterResponse()` — осознанное решение (DEPLOY.md).
- **Не возвращать тёмную тему / theme-toggle** — light-only закреплён тестом `FrontendPolishTest::test_site_is_light_only_without_theme_toggle`.
- **Не менять `'timezone' => 'UTC'`** в `config/app.php` без сквозной ревизии: даты хранятся как киевское wall-clock и вручную шифтуются в 5 местах (см. Gotcha «Таймзона»).
- **Catch-all `/{page:slug}`** находится в конце `routes/public.php`, украинская регистрация остаётся последней в `routes/web.php`; новый top-level путь → добавить в регексп исключений в той же правке.
- **Не запускать `db:seed` / `SiteSeeder` на окружении с реальным контентом** — сидер деструктивен (delete меню, персонала, видео, баннеров).
- **`public/build/` в git не коммитить** (он в `.gitignore`) — прод-бандл собирает деплой-workflow `deploy.yml` и заливает rsync-ом. Локально для проверки — `npm run build` или `npm run dev`.
- **Деплой:** push в `master` = автодеплой на прод (`.github/workflows/deploy.yml`). Не пушить в `master` без явной просьбы пользователя (правило «не коммитить/не пушить» теперь ещё и деплоит).
- **`ARCHITECTURE.html` и прочие HTML-твины руками не редактировать** — только `node DocsHtml/generate.mjs`.
- Слаг `istoriya` (drop cap) и страница `abituriyentu` (7 хардкод-ссылок) — не переименовывать без правки шаблонов и тестов.
- `NewsObserver` подключён атрибутом `#[ObservedBy]` на модели `News` — помни про Telegram-сайд-эффект при любых правках новостей.

## PoC-элементы

Проект — PoC: часть путей/кнопок/данных в прод не пойдёт. Правила:
- Добавляешь новый временный путь, кнопку, заглушку, хардкод — **сразу** вноси строку в таблицу «PoC-only» в ARCHITECTURE.md (в той же правке).
- Удаляешь/финализируешь PoC-элемент — убери его строку оттуда же.
- Полный текущий список — ARCHITECTURE.md → «PoC-only».

Храни только последнюю запись, без накопления журнала. Для незавершённой задачи не заявляй завершение. Перед финальным ответом проверь совпадение общих частей файлов.

## Карта работы и проверки

- Публичные страницы: `routes/web.php` → общая карта `routes/public.php` (украинские имена и `/en` с именами `en.*`) → `app/Http/Controllers/` → `app/Models/` → `resources/views/`. Общий layout — `resources/views/components/layouts/app.blade.php`.
- Админка: `app/Filament/Resources/`, `Pages/`, `Widgets/`; настройка панели — `app/Providers/Filament/AdminPanelProvider.php`.
- Схема и контент: `database/migrations/`; внешние интеграции — `app/Services/`, `app/Observers/`, `app/Jobs/`, `app/Mail/`.
- Локальный сервер: `php artisan serve --port=8002`. `composer run dev` дополнительно запускает очередь, pail и Vite; это dev-скрипт, а не описание прод-инфраструктуры.
- PHP: `composer test`; точечная проверка — `php artisan test --filter=ИмяТеста`. `phpunit.xml` задаёт SQLite `:memory:`, mail/cache/session в памяти и синхронную очередь. `tests/TestCase.php` включает сидирование и отключает Vite, поэтому PHP-тесты не проверяют сборку фронтенда. До запуска убедись, что окружение тестовое и нет закэшированного production-конфига.
- Фронтенд: `npm run build`; воспроизводимая установка из lock-файла — `npm ci`. Для PHP используй `composer install`, без незапрошенного обновления зависимостей.
- Документация: проверь локальные ссылки и `git diff --check`; при изменении `ARCHITECTURE.md` обязательно запусти `node DocsHtml/generate.mjs`. Для правок только документации PHP-тесты и сборка фронтенда не обязательны.
- `.claude/launch.json` задаёт запуск сервера; `.claude/settings.json` содержит shell-hooks для защиты и регенерации HTML архитектуры. Hooks используют POSIX shell и `/usr/bin/python3`; их работу в Windows нельзя считать проверенной. Codex выполняет эти правила из `AGENTS.md`, не полагаясь на Claude hooks.
- Не перезаписывай существующий `.env`, не сохраняй секреты в документацию. Установки, миграции и сидирование не являются обязательной частью ознакомления с проектом.

## Прямой доступ к БД тестового хостинга

Параметры прямого подключения к MySQL тестового хостинга just-test.shop находятся в отдельном локальном файле [`.env.hosting.local`](.env.hosting.local). Перед работой с удалённой БД прочитай этот файл; он исключён из Git через `.gitignore`. Если файла нет в новом checkout, запроси реквизиты у пользователя, не используй локальный `.env` вместо них.

- Прямое подключение проверено 2026-10-04 через PHP PDO MySQL: чтение доступно. На момент проверки — 33 таблицы, 213 страниц и 513 новостей.
- Пользователь разрешил агентам напрямую изменять эту тестовую БД в рамках запрошенных задач, включая перевод материалов. Отдельное разрешение на каждую обычную правку в рамках такой задачи не требуется. Эти параметры относятся только к тестовому хостингу.
- Не подменять локальный `.env` этими параметрами и не запускать PHP-тесты на удалённой БД. Для подключения использовать отдельное соединение; перед записью проверить выбранную БД и фактическую схему. Поля английского перевода нельзя считать существующими только по локальному коду.
- Перед изменением материала сохранить его исходные значения для восстановления; связанные записи изменять в транзакции, где это поддерживается. Проверять результат чтением. Не перезаписывать существующие переводы без соответствующей задачи.
- Не запускать `db:seed`, `SiteSeeder`, `migrate:fresh` и массовое удаление. Изменения схемы оформлять миграциями проекта; не создавать расхождение схемы хостинга и кода ручным DDL.
- При прямом SQL обновлении учитывать обход Eloquent observers, Telegram-сайд-эффектов и сброса кэшей (`settings.map`, `menu.navigation` и других). Не считать изменение на сайте видимым до проверки актуальности кэша.
- Синхронизация контента тестовой БД с otfk.od.ua (2026-10-05/06): рабочая папка — игнорируемая `storage/app/private/sync-2026-10-05/` (`AGENT_GUIDE.md` — регламент; кэш оригинала `orig/`, `compare.py` — пословное сравнение по маркеру `<!--imported-from:URL-->`, `apply.php` — патчи через модели `saveQuietly()` с бэкапом в `backup/`, обязательным `*_en` для изменённых полей и пересчётом хеша, `show.php` — чтение записи; отчёты зон — `reports/`). На хостинге уже лежат фото новостей `/storage/news/imported/<имя из /uploads/>`.
- Массовый импорт переводов в тестовую БД (2026-10-05) делался скриптом через модели с отдельным подключением `hosting`: `saveQuietly()` без timestamps (без NewsObserver/Telegram и без изменения `updated_at`), хеш — `currentTranslationSourceHash()`, проверка неизменности оригинала с момента экспорта, затем удаление ключей `settings.map`/`settings.translations`/`menu.navigation` из таблицы `cache`.
